# Sync in the add-on (phase 6) — Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A student with the add-on gets a prompt when a newer release exists and,
on accepting, their Doctorine notes' Text and Extra are updated in place by guid,
plus any media those fields need. Nothing else in their collection is touched.

**Architecture:** The server answers "what changed between release A and B" from the
revisions table (changed Text/Extra, added notes, retired guids) and lists the media
filenames those fields reference. The add-on computes a plan from that payload and
the local collection in a pure module, shows it, then applies it on the main thread
with Anki's own API (`mw.col.update_note`, `mw.col.add_note`) with a log and a
dry-run. The local release version lives in `user_files/sync.json`.

**Tech Stack:** stdlib; aqt/anki APIs only inside `__init__.py`.

**Spec:** `docs/superpowers/specs/2026-10-01-online-deck-and-sync-design.md`, §8.
Decision: sync adds new notes as well as updating; local edits are overwritten and
the prompt says so.

---

## Task 1: server sync payload
- [ ] Tests (`server/tests/test_sync_api.py`): `GET /api/sync?since=1.0` with current
      1.2 returns `{from, to, changed: [{guid, fields:{Text,Extra}}], added: [{guid,
      note_type, fields, tags}], retired: [guid], media: [filenames]}`; `since=1.2`
      → empty; unknown `since` → full diff from the first release with
      `baseline_missing: true`; a note changed in 1.1 and again in 1.2 appears once
      with its final text; media list = filenames referenced by changed/added
      fields that exist on the server.
- [ ] Implement `sync_payload(conn, since)`; route is public (ids + text of changed
      cards only, which every student already has).
- [ ] Commit.

## Task 2: add-on plan (pure)
- [ ] Tests (`addon/tests/test_sync_plan.py`): `plan(payload, local)` where local =
      {guid: {"nid", "fields", "mod"}} → updates (guid, nid, new fields), adds,
      skips (guid not in collection, retired handled as skip with reason), and a
      flag per update when local text differs from payload "before" (student
      edited; overwritten, counted); media to fetch = payload media minus local
      media dir listing.
- [ ] Implement `addon/sync_plan.py`; commit.

## Task 3: add-on wiring
- [ ] `sync.json` state (version, last_check); check on profile open (background,
      once per 12h, or Tools → Check for deck updates); prompt dialog:
      "Release 1.2: N cards updated, M new. Updating replaces any edits you made to
      these cards. [Update now] [Later]" with a changelog link.
- [ ] Apply on the main thread in batches with a progress bar; `mw.col.update_note`
      for changes (fields only, tags untouched), `mw.col.add_note` into the deck
      named like the student's Doctorine deck (default "Doctorine v2") for adds;
      media via `mw.col.media.write_data(name, bytes)` fetched from `/media/<name>`;
      retired notes untouched (listed in the log only); then store the version and
      refresh the official set.
- [ ] `--dry-run` style: a "Preview" button lists what would change without writing.
- [ ] Every step logged to `doctrine.log`; failures never leave the collection
      half-updated: apply per note inside `mw.col` undo checkpoint, continue on
      per-note error, report counts.
- [ ] Import smoke test; packages.

## Task 4: verify
- [ ] Unit suites green. On production: with a real pending edit, cut and build 1.1,
      then in the throwaway profile with v2 imported: Check for deck updates →
      prompt shows 1.1 → Update → the edited card shows the new text, tags
      unchanged, note count unchanged, Anki's own sync not forced.
